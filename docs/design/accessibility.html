Accessibility & Getting Started — Portable Dev Studio

Status: v1 — first draft. This document explains how anyone with a cheap laptop and public Wi-Fi can use this project as a portable AI coding environment.

1. What is this?

This is a self-contained, portable workspace for AI-assisted software development. The folder itself is the product — rules, inventory, tools, and configuration all live here. You can archive it, move it to another machine, unpack it, and continue working without missing pieces.

The goal: answer three questions at any time:

  1. What do we have? — machines, services, model providers, models, keys, tools.
  2. How do we use it safely? — where secrets live, what may read them, what is forbidden.
  3. How do we continue on another machine? — what travels in the archive, what is recreated, what is verified afterwards.

2. Who is this for?

This workspace is designed for anyone with a cheap laptop and public Wi-Fi. You do not need expensive hardware, cloud accounts, or paid model subscriptions. Everything runs locally or through free API tiers.

5. How to use it (step by step)

Step 1 — Get the folder

Clone or copy this project folder to your machine:

git clone <repository-url>
cd Default Project

Step 2 — Verify the environment

Run auto-discovery to check Python, git, bash, and database:

python3 tools/autodiscovery.py

Expected exit code: 0 (OK). If missing, install git or bash first.

Step 3 — Create the inventory database

The local SQLite database is recreated from committed SQL files:

python3 tools/inventory.py init

This creates data/inventory.db (local only, never committed to git).

Step 4 — Add your API keys

Add at least one LLM provider key. Keys are stored in your OS native credential store (KWallet, secret-tool, Keychain, Windows Credential Manager, or TDE DCOP):

python3 tools/secret.py --backend auto setup

Then set a key (value is read from prompt, never printed):

python3 tools/secret.py --backend auto set nvidia/personal/api_key

Step 5 — Start an agent

Use any supported agent harness:

  • OpenCode (primary): opencode run
  • Goose: goose session (goose on PATH)
  • Claude Code / Codex CLI / Gemini CLI / Rex — supported but secondary

Ask the agent to read AGENTS.md first — it defines the project rules.

7. Security rules

  • Secret values never enter git, the archive, or any project file.
  • The primary store is the operating system's native credential store.
  • auto never falls back to plaintext — use --backend file explicitly.
  • Values are never logged or included in exception messages.
  • data/inventory.db is gitignored and recreated locally.
