Gaps and the adapter fix

  1. Subagents. Native subagents exist in Claude Code, opencode, goose, codex and gemini CLI, but with different rules: goose only in autonomous mode, gemini and goose without nesting, rex none by design, aider none. The owner saw subagents fail on about half of the runtimes (2026-11-22). Fix: the adapter declares a subagents capability only where a smoke test proves it; elsewhere spawn_role() falls back to the one-shot process above. When even that is not wanted, docs/procedures/orchestration.md "No subagents" (one agent plays the roles in turn) stays the last fallback.
  2. The fallback conflicts with two current rules. AGENTS.md says never start claude, gemini, goose, codex or another opencode process unless the user names it in an order, and RUNTIME-ADAPTERS.md Rule 4 says one runtime process per session. The fallback needs both rules amended: the adapter (not the model) may start one child of the same runtime per role, only when the user ordered orchestrated work, and the child gets the same rules file and the same deny list. Until that is decided and written, the fallback is design only.
  3. Guards are not equal. A blocking pre-tool hook is documented for Claude Code, codex, gemini CLI and rex. opencode has a permission evaluate hook that can deny, but whether execute.before can block is not documented. goose has no documented hook; aider has none. On those runtimes the push guard (confirm_push()) and the secret rules are instructions plus permission settings, not enforcement. Say so in each adapter's capability set; do not claim a guard that is not there.
  4. Hooks in a child process. A separate process loads its own config: Claude -p runs the project hooks without a trust dialog [C2]; codex runs project hooks only after they are trusted [X1]; rex reads hooks and permissions only from the user config [S3]. The adapter must check, per runtime, that the guard is active in the child before it starts one.
  5. Skills reach. .claude/skills is read by Claude Code, opencode and goose; .opencode/commands only by opencode. codex reads only .agents/skills, gemini CLI .gemini/skills or .agents/skills, rex .rex/skills. A shared .agents/skills folder (same thin pointers to docs/procedures/) would cover codex, gemini CLI, opencode and goose; rex needs its own folder or a skills.paths entry, plus trust.
  6. Rules reach. rex reads the project AGENTS.md only with workspace.trust: true; aider reads nothing by itself and needs --read AGENTS.md. Without these the agent runs without the workspace rules. Whether this explains "rex partially" on 2026-11-22 is not verified.
  7. Endpoint formats. One kiko endpoint does not serve all runtimes: Anthropic format (Claude Code), OpenAI chat format (rex, opencode, goose, aider), Responses API (codex), Gemini format (gemini CLI). The adapter records which format each runtime needs.
